# ゲーム制作 仕様書・プロンプト（改訂版）

## AIへのお願い（作業ルール）

- この文書はゲーム全体の仕様です。一度に全部を作らず、指示された範囲だけを進めてください
- 実装はまず方針やヒントを示してください。完成コードは頼まれたときだけ書いてください
- 難易度の高い問題では、いきなり結論を出さず、途中の思考過程も示しながら進めてください
- 不明な点がある場合は、まず質問してください
- 不確かな情報や推測を含む場合は、断定せずにその旨を明示してください
- このゲームには**意図的に仕込んだバグ（偽バグ）**があります。偽バグは修正しないでください。意図的かどうか分からない挙動を見つけた場合は、直さずに質問してください

## 基本方針

- エンジン：Godot 4.7.2（言語は GDScript を想定）
- **2Dゲーム**（決定）
- メインジャンルは RPG（横スクロール）
- 2Dだが、異なる角度からの視点を組み込む（疑似3D）
  - 例：横スクロールで進んでいて、ある地点で特定の操作をすると見下ろし視点に切り替わる
- RPGを軸に、ギミックとして別ジャンルを取り込み、自由度の高いゲームにする
- PCでプレイする

## コンセプト

### 2つのルート

- **通常ルート**：バグを使わなくてもクリアできる。ただし罠や敵が多く、かなり遠回りしてようやく魔王のもとにたどり着く
- **バグルート（イフルート）**：このゲームの本質。壁抜けや、特定の敵・罠の無効化などを使うと、魔王のもとへ一気に近道できる
- 「バグありき」ではない。バグを見つけなくてもクリアは可能

### バグの設計

- バグはすべて最初から意図して作っておく
- バグによって攻略方法が変わる
- バグとバグを組み合わせると、新しいバグが生まれる
- ステージを重ねるごとに、難易度とギミックの数を徐々に増やす（時間があれば）

### チュートリアル

- かなり丁寧に作る
- 最初に「どういう動作ができるか」をプレイヤーに提示する
- 「これとこれを組み合わせたら、これができるのでは？」という発想へ誘導する
  - 例：しゃがむ → 当たり判定が変化する → ダッシュと組み合わせて壁抜け

### バグ発見の判定【要検討】

- Bug（虫）を見つけると「バグを見つけた」判定になる
- 「バグを見つけた」のに「見つけた判定にならない」バグも存在する

## ギミックの発動条件（案）

以下の操作でフラグが立ち、何らかのギミックが発動する。

- WASD 全押し
- ドット絵のいびつな部分・特定の部分をクリックする
- パスワード入力欄に、本来のパスワードではない特定の語を入れる（ゲーム内の情報から導ける語にする）
- コマンド欄に特定の語を入力する（後述の `break;` など）
- バグが発生したときだけ起こるイベント

## バグ・ギミックの具体例

- 簡単な迷路の行き止まり → 壁抜けできるのでは？と気づかせる
- 横スクロールでの壁抜け
- 視点の切り替え（横スクロール → 見下ろし）
- のほほんとしていたら、脈絡なく別ジャンルのゲームが始まる（例：突然シューティング）
- 別ジャンルのゲームのクリア報酬で、魔王城の「開かずの扉」（バグなしでは絶対に開かない）の鍵を入手する。その別ジャンルのゲーム自体も、バグを使わないと発見できない
- 無限ループ：バグルートで、敵を倒してクリアしても最初に戻ってしまう
  - 脱出方法1：Enter キー（return）を押すと、そのゲームを `return;` して強制終了できる
  - 脱出方法2：どこかで break ボタンを発見する、またはコマンド欄に `break;` と打つ
- バグとの戦闘
- バグを見つけるとバフになる【要検討】

## 拡張案（優先度低・時間があれば）

- 全バグを見つけると、プレイヤー自身がバグの視点になる
  - デバッグするプレイヤーから逃げる
  - そのときの「デバッグするプレイヤー」は、自分のそれまでの動きをトレースした BOT
- バグから見つけた抜け穴で、ゲーム自体を創造しなおす
