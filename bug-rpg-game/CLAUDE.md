# CLAUDE.md

## プロジェクト概要

2Dのアクションゲーム（基本は画面固定）。PC向け。
「アイテム」を獲得してボスを倒すために「試練の間」に挑戦していく。試練の間は層（ステージ）に分かれていて、1層につき1つの新しい操作（壁抜けなど）を覚える。
最初はボスになすすべなく倒されるが、アイテムで強くなり、最終的に倒せるようになる。
エンジンは Godot 4.7.2（言語は GDScript を想定）。

2026-09-28 に方針を変更した（元の資料は `docs/方針変更.md`）。以前は「普通のRPGに意図的なバグ（偽バグ）を仕込み、それを見つけて攻略に使う」横スクロールRPGだった。

## 仕様としての「バグっぽい操作」のルール（最重要）

- 壁抜けなど、一見バグに見える操作は、このゲームの仕様（操作方法のひとつ）。修正しない
- 意図的かどうか分からない挙動を見つけたら、直さずに質問する
- 目印は方針変更後も継続：一覧 `data/fake_bugs.json` を正とし、コードには `# FAKE_BUG: id` のタグを付ける。タグがある箇所は触らない。新しい「バグっぽい操作」を作ったら一覧とタグを追加し、`godot --headless --path . --script res://tools/check_fake_bugs.gd` で検査する

## 決定事項（方針変更後）

詳細は `docs/プロンプト.md` を参照。

- 基準解像度：480x270（2026-09-28 に 320x180 から変更。主人公の画像 32x32 に合わせるため）、整数倍拡大（ドット絵。フルスクリーン 1920x1080 でちょうど4倍）。ストレッチモードは `canvas_items`（文字をくっきり表示するため）、起動はフルスクリーン、ウィンドウ表示時は 1440x810（3倍）
  - 試練の間の寸法・速さ・当たり判定は、320x180 のときの値をすべて1.5倍にしている（遊んだ感触は変えていない）。主人公は `scenes/trial_player.tscn`（`player.gd` の `world_scale = 1.5`、当たり判定 15x30、しゃがみ 15x15）
  - 方針変更前のシーンは 320x180 のまま（`scenes/player.tscn` は `world_scale = 1`）。今の解像度で開くと画面の左上に小さく寄って見える
- 画像：`assets/` に置く（例：`assets/characters/player/`、`assets/characters/boss/`）。主人公は右向き1枚（32x32。描かれている範囲は 18x32）と待機モーション2コマ（`taiki.png`）。左向きは左右反転で表示、しゃがみは縦に縮めて表示（しゃがみ用の画像ができるまでの仮）。ボスは 64x64 のノーマル4枚と赤（被ダメージ）4枚で、1秒で4枚のループ、被ダメージ時は「ノーマル1→赤1→ノーマル2→赤2…」と交互にする
- 画面は基本固定（1画面で1層）
- BGM・テクスチャ・導入のストーリーは別の人が担当。できしだい統合する。それまでは四角などの仮グラフィックで作る
  - 届いた画像は元のファイルを残したまま、`tools/convert_art_assets.gd` で使える形に変換する（実行後に `--import`）。ビーズ図案（`bead-pattern*.png`。1マス30ピクセルに拡大し、方眼の点が入った画像）は等倍のドット絵に戻す：杖 `assets/stick/staff.png`・盾 `assets/shield/buckler.png`・マント `assets/mant/mantle.png`（48x48）。試練の間の背景（JPEG）は横幅480に縮めて `assets/background/shiren/trial_background.png`。ボス戦の背景（細かい1枚絵の JPEG、1376x768）は縮めずに 16:9 に切るだけで `assets/background/BOSS/boss_background.png`（1365x768）
  - 試練の間の背景：`scenes/trial_background.tscn`（画面に固定。スクロールしても動かない。上下15ピクセルずつ切れる）を第一〜三層に置いている
  - アイテムの絵：各層のオーブは杖（第一層）・盾（第二層）・マント（第三層の「魔導士のローブ」）の絵（`orb.gd` の `texture`。24x24 で表示）。獲得の演出とアイテム一覧のアイコンも同じ絵（`Inventory.ITEM_IMAGES`。36x36 で表示）
  - BGM：Autoload `Bgm`（`scripts/bgm_player.gd`）が流す。タイトル `assets/BGM/title/Epilogue_loop.ogg`、試練の間 `assets/BGM/shiren/village.mp3`、ボス戦 `assets/BGM/BOSS/Battle-Vampire_loop.ogg`、仮のエンディングは無音。同じ曲のままなら層のやり直しや次の層でも最初からにならない。ループはインポート設定（loop=true）。Godot は m4a を読めないので、BGM は ogg か mp3 で受け取る
- 境界：画面の上下左右の端に、境界だと分かる太さの四角い枠を置く。画面に貼り付けず、ステージ側に置く
  - 左の境界には進めない（後戻りできない）
  - アイテム未獲得で右の境界に触れると、1秒ほど暗転して同じ層を最初からやり直す。獲得済みなら、1秒ほど暗転して次の層へ
- 各層の開始時（やり直し時も）に「～試練の間　第〇層～」（漢数字）を1秒ほど表示してフェードアウト
- 各層のヒントは、スタート地点付近の看板（「Tips:～」）で出す。E キーで読む
- アイテム（オーブ）獲得時は『「〇〇」を獲得した！』の演出（以前のカギ入手の演出を流用）。演出の間（約2.5秒）はゲーム内の時間を止め、画面を少し暗くして、獲得したことをはっきり見せる。演出中は Esc メニューも開かない
- 「バグを発見！」の演出は削除した（壁抜けなどはバグではなく仕様になったため）。`BugRegistry` による発動・発見の記録は残っている
- 敵は当面置かない
- タイトル画面：中央にタイトル（文字）とボタン（「試練の間に入る」「アイテム一覧」「設定」「ゲームを終了」）。右下に「BOSS」アイコン（ボスへの挑戦）。簡易的なものでよい
  - アイテム一覧（`scenes/item_list.tscn`、`scripts/item_list.gd`）：試練の間のアイテムを順に並べる。持っているものは絵と名前、持っていないものは影（`shaders/silhouette.gdshader`）と「？？？」。「閉じる」か Esc で閉じる
- アイテムの保存：`Inventory` が試練の間のアイテムだけを `user://save.cfg`（Windows では `%APPDATA%/Godot/app_userdata/Bug_Rpg_Game/save.cfg`）に記録し、起動時に読み込む。タイトルの設定の「全データリセット」で消せる。テストでアイテムを取ると記録されるので、テストの前に `save.cfg`・`settings.cfg` を退避し、後で元に戻すこと（遊んだ記録が入っていることがある）
- Esc メニュー：タイトルへ戻るボタンと「設定」。戻るボタンは、試練の間（group `trial_floor`）では「試練の間を出る」、それ以外では「タイトルへ」と表示する（押したときの動きはどちらもタイトルへ）。「設定」はタイトルと同じ設定画面を開く（設定画面を開いている間の Esc は設定画面だけを閉じる）
- 設定（タイトルと Esc メニューの「設定」、`scenes/settings_menu.tscn`）：ミュート（切り替え）と音量（スライダー、0〜100%、5%きざみ）。変えるとすぐ全体の音量（Master バス）に反映し、Autoload `Settings`（`scripts/settings.gd`）が `user://settings.cfg` に記録する
  - タイトルの設定だけ「全データリセット」ボタンを出す（`settings_menu.gd` の `show_reset`）。押すと確認（最初に選ばれているのは「やめる」）を出し、「消す」で獲得したアイテムと音の設定を最初の状態に戻し、`save.cfg`・`settings.cfg` も消す
- 待機モーション：主人公（試練の間・ボス戦）は、1秒以上動かないと `assets/characters/player/taiki.png`（32x32 のコマが横に2枚。1枚目は立ち絵と同じ）を0.5秒ごとに交互に表示する。試練の間は床の上で立っているとき、ボス戦は移動キーを押していないとき。しゃがむ・動くとすぐ戻る。`player.gd`・`boss_player.gd` の `idle_texture` を設定したものだけ（方針変更前のシーンの主人公には出ない）
- 試練の間の壁や障害物（`block.gd` を使うもの。境界も含む）には、内側のふちに1ピクセルの枠線を付ける（`trial_floor.gd` が `enable_outline` を呼ぶ）。色は `shaders/block_outline.gdshader`（設定は `shaders/block_outline.tres`）が、枠線の真後ろの背景の明るさで決める（暗いところは白っぽく、明るいところは黒っぽく）。背景の細かい模様でちらつかないよう、ぼかした背景（ミップマップ）で明るさを見る。方針変更前のシーンには付けない
- 操作（試練の間）：ジャンプは W・Space・矢印の上。しゃがみは S・矢印の下
- 第一層：基本操作の看板（左右移動・しゃがみ・ジャンプ・ダッシュ）、少しの障害物、右の境界付近にオーブ（「はじまりのつえ」）
- 第二層：新しい操作は壁抜け（しゃがみ＋ダッシュ）
  - 抜けられる壁は2か所ほどで、色を変える。右の境界だけ、抜けられる壁と同じ色にする
  - 右の境界を壁抜けすると横スクロールが始まり、先にオーブ（「風神の盾」）がある。「端だと思っていたものに、実はまだ奥があった」という体験
  - 右の境界にただ触れると戻される。壁抜け中だけ戻されない
  - オーブ獲得後に白い扉が現れ、近づくと「入る」と表示。E で次の層へ（当面は境界だけの部屋）
- 第三層（`scenes/trial_floor_3.tscn`、`scripts/trial_floor_3.gd`、アイテムID `mage_robe`「魔導士のローブ」。絵はマント）：新しい操作はしゃがみジャンプ（第三層だけで使える。`trial_player` の `can_crouch_jump`）
  - しゃがみジャンプ（`player.gd`）：床の上でしゃがんだまま1秒たつと、ため状態（白っぽく点滅）。しゃがんだまま歩いてもためは続く。ため状態でジャンプキーを押すと、立ち姿勢に戻って約140ピクセル跳ぶ（普通は約75）。しゃがみを押しているだけでは跳ばないので、ため状態でも壁抜けできる。しゃがみを離すか、壁抜けで壁を通り抜けると解除。頭の上に立つ空間がないと跳べない
  - 壊せるブロック（`scenes/breakable_block.tscn`、明るい橙色にひびの線）：しゃがみジャンプで上昇中に下から当たると壊れ、破片が飛び散る。頭はブロックの下辺の位置でぶつかって止まるので、もう一度跳ばないと登れない。層をやり直すと元に戻る
  - 看板：「Tips:ちょっと疲れたからしゃがもうかな...」
  - 段の高さは不ぞろい（床の上面 y：下段258・中段195・上段66。段の高さは下段54・中段120・上段54、床の厚み9）。中段は「しゃがみジャンプでしか届かない足場（床から80以上）の上に、主人公の背（30）が入る空間」が要るので高くしている
  - 下段：右へ進む。低い段（ジャンプで乗る）と低い天井（しゃがみ歩きでくぐる）が2つずつ。右の境界の手前の天井（x=414〜438）が壊せるブロックで、壊して中段へ
  - 中段：左へ進む。柱（しゃがみジャンプで越える）→ 低い天井（しゃがみ歩き）→ 高い足場（しゃがみジャンプでしか届かない）→ 左の約1/4が上段への吹き抜け（しゃがみジャンプで乗る足場から上段へ）
  - 上段：上の境界が壊せるブロック（`trial_border.gd` の `top_breakable`）。壊すと境界全体が壊れ、画面の上に続く場所へ出られる（上の境界より上に出るとカメラが縦にスクロール）。1マス（18x18）の足場を、ぎりぎり届く高さ（132ピクセル上）で3つ、しゃがみジャンプで登った先にオーブ。落ちても上段まで落ちるだけ
  - オーブを取ると、3つ目の足場の右側に道が左から右へ伸び（0.8秒）、その先に白い扉が現れる。扉の先は仮のエンディング（`scenes/ending.tscn`。「エンディング（仮）」と「タイトルに戻る」）
  - 偽バグ一覧には `crouch_jump`・`top_boundary_break`（どちらも発見数に数えない）として登録
- ボス戦（`scenes/boss_battle.tscn`、`scripts/boss_battle.gd`）：タイトルの「BOSS」から入る。シューティング
  - フィールドは画面全体（境界の枠で囲む）。背景は1枚絵を画面の大きさ（480x270）に滑らかに縮めて表示（`boss_battle.tscn` の Background。フルスクリーンでは元の画像の細かさがほぼそのまま見える）。ボスは画面の中央（`scripts/boss_sprite.gd`、1秒で4枚のループ）
  - 自機（`scenes/boss_player.tscn`）：WASD / 矢印で8方向（斜めあり）に移動。右に動くと右向き、左に動くと左右反転。弾との当たり判定は体の中心の 6x6 だけ。HP は5で、当たると約1秒無敵（点滅）
  - Ctrl（しゃがみ。ボス戦専用の入力 `boss_crouch`。C はチャージ攻撃に使う）＋ Shift（ダッシュ）＋ WASD で押した向きにダッシュ（向きを押していなければ最後に向いた左右）。ダッシュ中の0.3秒だけ黄色い球をすり抜ける（次に使えるまで0.5秒）。赤い球は抜けられない（`boss_bullet_clip`、発見数に数えない）
  - 攻撃の順番：通常弾（約4秒）→ 大技 → 通常弾 → 一斉射撃 → …。30秒たったら間隔を8割にする
    - 通常弾：ボスの周り3か所に小さな赤い魔法陣（0.3秒）を出し、そこから自機を狙って撃つ
    - 大技：赤い魔法陣（1.2秒）→ 全方向に円形の赤い弾を2重に撃つ。どちらの円にも、くぐれる隙間が4か所ある。弾の速さは、よけられるぎりぎりを目安に調整
    - 一斉射撃：黄色い魔法陣（1.2秒、四角を重ねた模様）→ 黄色い弾を正方形に隙間なく並べ、正方形のまま広げる。しゃがみダッシュでしか抜けられない
  - 魔法陣は回転し、発射の直前に光る（`scripts/magic_circle.gd`）。見た目は仮のドット絵で、`tools/generate_magic_circles.gd` で1ピクセル単位の線を描いて `assets/battle/magic_circle/`（big_red.png・yellow.png 128x128、small_red.png 16x16）に書き出したものを読み込む。描く担当の人の画像ができたら同じファイル名で置き換える。回転するので、線は少しギザギザに見える
  - 魔法弾は画像（赤：`assets/battle/bullet/normal/shot_fire01_03.png`、黄：`assets/battle/bullet/through_wall/shot_light02_01.png`。どちらも 32x32 のコマが横に4枚）。半分の 16x16 で表示し、1秒に2周アニメーションする（弾ごとに開始のコマをずらす）。弾の当たり判定は半径4
  - 処理を軽くするため、弾は1発につき画像を1回貼るだけにし、赤→黄色の順にまとめて描く（図形で描いていたときは、一斉射撃で約7fps まで落ちていた）
  - ボスの体に触れてもダメージを受ける（当たり判定は 40x24）
  - HP が 0 になると「GAME OVER」。下に「リトライ」（左）と「タイトルに戻る」（右）。最初に選ばれているのはリトライ
  - 経過時間は表示しない。ボスの HP（200）は画面上部にバーで表示
  - 自機の攻撃（`boss_player.gd` が撃つ合図を出し、`boss_battle.gd` が弾を動かす）。どちらも撃った瞬間のボスの方向へまっすぐ飛ぶ。当たるとボスの被ダメージ演出（1周し終わるまでは連続で当たってもやり直さない）
    - 通常攻撃：Space（入力 `shoot`）を押している間、0.15秒ごとに連射。画像は赤い魔法弾と同じ。ダメージ1。「はじまりのつえ」を持っているときだけ撃てる
    - チャージ攻撃：C（入力 `charge_shot`）を押してから1秒たつと自動で撃つ。1秒たつ前に離すと何も出ない。撃ったあとは押し直す。ダメージ5。画像は `tools/convert_art_assets.gd` でビーズ図案8枚（2〜7・9・10番）を横に並べた `assets/battle/bullet/charge/charge_sheet.png`（0〜3：ためている間、4：ため終わり、5：飛んでいく弾、6〜7：当たったとき）。「魔導士のローブ」を持っているときだけ使える
  - 「風神の盾」を持っていると、1回だけダメージを受けない（HP の横に盾の絵。防ぐと消え、自機の上に盾の絵が一瞬出る。無敵時間は普通に当たったときと同じ）。リトライで戻る
  - ボスの HP が 0 になると、弾を消してボスが消え、「GAME CLEAR」と表示するだけ（戻るときは Esc メニューの「タイトルへ」）
- 保留・未決定：GAME CLEAR のあと、シナリオとの関係、進行状況の扱い（入るたびに第一層からか など）、設定画面の音以外の項目、エンディングの中身（今は第三層クリアで仮のエンディング）

    - 真ん中に床から生えた柱（x=228〜252、上端 y=90）。それを挟んで、天井から生えた壁2本（x=132〜150 と x=330〜348、下端 y=177）を線対称に置く
    - 足場は、上から生えた壁の内側（上端 y=144。左 x=150〜198、右 x=282〜330）と、柱の左右（上端 y=204。x=198〜228、252〜282）。上の段と下の段が横に重ならないようにしている（重なると、ジャンプで下の段から上の段へ登るときに頭をぶつける）
    - 登り：床 → 柱の左の足場 → 左の壁の足場 → 柱の上。降り：柱の上から右へ → 右の壁の足場 → 左へ → 柱の右の足場 → 右へ → 床、と1段ずつ降りられる
    - 左右の上から生えた壁の真下（y=186〜258）が、どちらも壁抜けできる壁。左を壁抜けしないと登り降りする場所に入れず、右を壁抜けしないと右の境界側へ出られない（上の壁との隙間9ピクセルは通れない）
    - 平らな所が続かないよう、スタートの先（x=78〜108）と右の出口の先（x=378〜408）に段差を置く。右の段差は、右の壁を抜けた勢いを止め、境界に近づきすぎないようにする役目もある
    - 段差は36〜40ピクセル（ジャンプは約50ピクセル）。柱の横の足場から柱の上へは直接届かない
    - 壁抜けできる壁の色は `trial_border.gd` の `CLIP_COLOR`（右の境界と同じ色）右の境界は `right_clippable` で壁抜けできる壁（layer 2）と同じ色になる。境界の外（x 480〜960）に出るとカメラの右の限界が広がって横スクロールし、先にオーブと白い扉（`scenes/exit_door.tscn`、オーブ獲得後に現れて「E: 入る」）がある。偽バグ一覧には `boundary_clip`（発見数に数えない）として登録
  - 右の境界の判定は毎フレーム行う。内側から触れていて、壁抜け中（`player.gd` の `is_clipping()`）でなければ、やり直しか次の層へ。外側から触れた場合は何も起きない
  - 第二層の白い扉の先は第三層。境界だけの仮の部屋 `scenes/trial_room.tscn` は今は使っていない
  - 同じアイテムを2回取った場合、取った扱いにはなるが、獲得の演出は初回だけ（アイテムを保存するようになったので、2回目以降に遊ぶときは演出が出ない。進行状況の扱いが決まったら見直す）

## 方針変更前の実装（すべて保留。削除しない）

以下は方針変更前の決定事項と、それに対応する既存の実装。今は使わないが、削除しない。

- 偽バグの管理：一覧 `data/fake_bugs.json`（項目：id、title、files、trigger、effect、requires、route、stage、hint、discovery、note）とコードのタグ `# FAKE_BUG: id` の併用。発動は `BugRegistry.trigger("id")`（Autoload）で記録。ずれの検査は `godot --headless --path . --script res://tools/check_fake_bugs.gd`
- バグ発見の判定：初めて「成功」したときに発見扱い（`discovery` が `normal` のもののみ）。「バグを発見！」とテントウムシの演出があったが、方針変更後に演出は削除した（発見の記録と BUG 図鑑のテントウムシ表示は残っている）
- 戦闘：コマンド式（ターン制）。敵の絵全体が画面に映った瞬間に暗転して戦闘画面へ（たたかう・ぼうぎょ・にげる）。倒した敵は `WorldState`（Autoload）に記録し、復活しない
- ポーズ：Esc でメニュー（RESUME / BUG / EXIT）。方針変更後は「タイトルへ」だけを表示し、この3つは非表示にしている（削除はしていない）
- BUG 図鑑：発見済みはテントウムシ、未発見はシルエット。表示名は `scripts/bug_book.gd` の `ENTRIES`。1ページ8枠
- チュートリアル（`scenes/stage_tutorial.tscn`）：通常ルートとバグルートの分岐。特定の壁を右→左→右と3回壁抜けすると3D迷路へ
- 3D迷路（`scenes/maze_backrooms.tscn`）：1人称、バックルームズ風、モノクロ（`shaders/monochrome.gdshader`）。ゴール前の光る壁だけ壁抜けでき、しゃがみ（Ctrl / C）はゴール前の区画のみ
- 見下ろしの2D迷路（`scenes/maze_topdown.tscn`）：正方形。真ん中の区画から4辺に壁抜けで出られ、ゴールにつながるのは1区画だけ。抜けられる壁は1ピクセルへこんでいる。形は `LAYOUT`（ASCII）で編集
- 縦シューティング（`scenes/shooter.tscn`）：左右移動のみ、Space で射撃。赤い弾はよける。隙間のない黄色い弾の列は、しゃがみ（S）＋ダッシュでだけすり抜けられる。ボスを倒すとカギ（`castle_door_key`）を入手して元の場所へ戻る
- 調べる操作：E キー（「E: CHECK」などの案内）。看板は `scenes/sign.tscn`、文章は `TextPrompt.show_message`（E / Enter / Esc で閉じる）
- 入力欄：共通の `TextPrompt`（Autoload）。開いている間はゲームを止め、Esc で閉じる。コマンド欄は端末を調べたときだけ、パスワード欄は扉ごと
- `stage_1`：扉は合言葉 OPEN で開き、DEBUG で無限ループの部屋 `stage_loop` へ。扉の手前に看板2つ
- `stage_loop`：右端で最初に戻り、敵も復活する。Enter のあと1秒以内に ; で `return;`、または端末で `break;` と打つと抜けられる
