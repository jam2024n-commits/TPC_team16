# CLAUDE.md

## プロジェクト概要

2Dの横スクロールRPG（視点切替による疑似3Dあり）。PC向け。
普通のRPGの世界に意図的なバグを仕込み、それをプレイヤーが見つけて攻略に使うゲーム。
エンジンは Godot 4.7.2（言語は GDScript を想定）。

## ドキュメント

作業前に、関係する部分を読むこと。

- 仕様：`docs/プロンプト.md`
- シナリオ：`docs/大まかな流れ.md`、`docs/序章.md`、`docs/1章.md`

## 偽バグのルール（最重要）

- このゲームには意図的に仕込んだバグ（偽バグ）がある。偽バグは修正しない
- 意図的かどうか分からない挙動を見つけたら、直さずに質問する
- 偽バグの目印：一覧ファイルを正とし、コードにはID付きのコメントタグを付ける併用方式（方針のみ決定）
  - コードに偽バグのタグがある箇所は触らない
  - タグも一覧もない不審な挙動は、直さずに質問する
  - ID：名前式（例：`wall_clip`）
  - タグの書式：`# FAKE_BUG: wall_clip`
  - 一覧ファイルの形式：JSON
  - 一覧ファイルの置き場所：`data/fake_bugs.json`
  - JSONの項目：id、title、files、trigger、effect、requires、route、stage、hint、discovery、note（全件で全項目を書く。空は `[]` か `""`。変更の可能性あり）
  - 現在の一覧の中身は例。必要に応じて削除・変更する
  - 偽バグの発動は `BugRegistry.trigger("id")`（Autoload、`scripts/bug_registry.gd`）で記録する。一覧にないIDはエラーになる
  - 一覧とタグのずれの検査：`godot --headless --path . --script res://tools/check_fake_bugs.gd`（偽バグを追加・変更したら実行する）
  - 未決定：偽バグの発動状態をセーブに残すか（今はメモリ上のみ）、`requires` の意味（全部揃ったら発生か、どれかでよいか）

## 決定事項

- 戦闘形式：コマンド式（ターン制）
- 視点切替：別シーンへ切り替え（見下ろし用のシーンを別に作る）
- 基準解像度：320x180、整数倍拡大（ドット絵）。ストレッチモードは `canvas_items`（文字をくっきり表示するため）、起動はフルスクリーン

- バグ発見の判定：初めて「成功」したときに発見扱い（`discovery` が `normal` のバグのみ。`undetectable` は発見扱いにならない）。発見時に「バグを発見！」とテントウムシのドット絵の演出を出す
- バグ発見そのものはバフにしない。バフはストーリー由来にする方針で、詳細は骨格の実装後に決める（保留）
- エンカウント：敵の絵全体が画面に映った瞬間に暗転し、戦闘画面に切り替わる（ステージは一時停止して上に戦闘を重ねる）。コマンドは「たたかう・ぼうぎょ・にげる」の3つ（仮）
- ポーズ：Esc でメニュー（RESUME / BUG / EXIT）。EXIT でゲーム終了
- BUG（実績のようなバグ図鑑）：発見済みのバグはテントウムシ、未発見はシルエットで表示。マウスを合わせると、発見済みは短い名前（例：「壁抜け」）、未発見は「？？？」を表示。開いている間はマウスを有効化。Esc で PAUSE メニューに戻る
  - 載せるバグと表示名は `scripts/bug_book.gd` の `ENTRIES` に、実装したものから追加していく
  - 今後複数ページになる前提（1ページ8枠。2ページ以上になると「<」「>」が出る）
- 視点切替（別シーンへ切り替え、決定済みの方式）の最初の例：
  - 特定の壁（例：`triple_clip`）を右→左→右と3回連続でwall_clipすると、迷路シーン（別シーン）へ切り替わる
  - 迷路は1人称の3D（バックルームズ風）。薄暗い照明で、この場面だけモノクロ表示（`shaders/monochrome.gdshader`）。シーンは `scenes/maze_backrooms.tscn`
  - 迷路は普通に歩いて進める。ゴールへの正規の入口はなく、ゴール前の壁だけ薄く光っており、そこだけwall_clipできる（`maze_goal_clip`）
  - しゃがみはゴール前の区画でのみ可能（Ctrl / C）。しゃがむと視点が少し下がる
  - 操作：WASDで移動、マウスで視点、Shiftでダッシュ。ジャンプはなし
  - ゴールに着くと暗転し、見下ろし視点の2D迷路（`scenes/maze_topdown.tscn`）へ切り替わる
  - ゴール前の壁抜け（`maze_goal_clip`）はただの壁抜けなので、発見数・BUG図鑑には数えない（`discovery` を `undetectable` にしている）
  - 座標・誘導・アイテムの内容は仮
- 見下ろしの2D迷路（3D迷路の続き）：
  - 正方形の迷路。暗転明けは真ん中の区画から始まる。真ん中の区画の4辺に壁抜けできる壁が1か所ずつあり、抜けると外側の4区画（風車状。互いにつながっていない）に出られる。ゴールにつながっているのはそのうち1区画だけ
  - 壁抜けできる壁の色はほかの壁と同じで、キャラクターが通れる幅（1マス）だけ。ほかの壁より少しへこんでいて（`RECESS`、今は各面1ピクセル）、目を凝らせば気付ける。両側から抜けられるので、はずれの区画からは戻れる
  - 壁抜けは最初から使える。操作：WASD / 矢印で上下左右に移動、Ctrl / C でしゃがみ（S は下移動に使うため）、Shift でダッシュ
  - 迷路の形は `scripts/maze_topdown.gd` の `LAYOUT`（ASCII）で編集できる
  - ゴールに着くと（`topdown_maze_clip`）暗転し、縦シューティングが始まる。この壁抜けは発見数・BUG図鑑には数えない
- 縦シューティング（2D迷路の続き、`scenes/shooter.tscn`）：
  - 自機は左右移動の1軸のみ（A/D・矢印）。Space で赤い弾を撃つ（自機が撃つのは赤い弾のみ）
  - 敵弾は2種類。赤い弾は普通によける。黄色い弾は隙間のない横一列で飛んでくる（普通にはよけられない）が、しゃがみ（S）＋ダッシュ（Shift）中は壁抜けの要領で当たり判定がなくなる（`bullet_clip`）。赤い弾はしゃがみダッシュでも当たる
  - ボスを倒すと「CLEAR!」のあとカギ（`castle_door_key`）を入手し、「カギを手に入れた！」の演出のあと暗転して、元のステージの元の場所へ戻る
  - HP は3。0 になると「GAME OVER」のあと、シューティングを最初からやり直す
  - `bullet_clip` は発見数・BUG図鑑に数える（仮。図鑑の表示名は「弾抜け」）
  - ボスの形・弾の配置・数値（HP、弾の速さ、黄色い弾の間隔など）は仮
- 調べる操作：E キー。調べられる物に近づくと「E: CHECK」などの案内が出る
- 看板：E で読む（`scenes/sign.tscn`）。文章は `TextPrompt.show_message` で出し、E / Enter / Esc で閉じる
- コマンド欄：ゲーム内の端末を調べたときだけ出る。パスワード欄：扉ごとに個別に置く。入力欄は共通の `TextPrompt`（Autoload）で、開いている間はゲームを止める。Esc で閉じる
- `return;`：Enter のあと1秒以内に ; を押すと `return;` として働く（Enter 単独はメニューなどの「決定」のまま）。今は無限ループの部屋でのみ効果がある
- 無限ループの最小版（仮の構成）：
  - チュートリアルのゴールで E を押すと `stage_1` へ進む
  - `stage_1` の扉の手前に看板を2つ置く：「コマンドは英語（OPENなど）です」「一部デバッグ用の機能が残っていますが，気にしないでください」
  - `stage_1` の扉は合言葉 OPEN で開く（通常ルート）。DEBUG を入れると、無限ループの部屋 `stage_loop` へ飛ばされる（バグルート）
  - ループ部屋は右端に着くと最初に戻され、敵も復活する。Enter→; か、端末で `break;` と打つと抜けて、`stage_1` のゴール手前に出る
  - 合言葉・看板の配置・ステージの配置・図鑑の表示名（合言葉 / return; / break;）は仮
- 倒した敵は `WorldState`（Autoload）に記録し、ステージを読み直しても復活しない。記録はメモリ上のみで、セーブは未対応。倒した敵以外のステージ内の状態は、読み直すとリセットされる
