# CLAUDE.md

## プロジェクト概要

2Dの横スクロールRPG（視点切替による疑似3Dあり）。PC向け。
普通のRPGの世界に意図的なバグを仕込み、それをプレイヤーが見つけて攻略に使うゲーム。
エンジンは Godot 4.7.2（言語は GDScript を想定）。

## ドキュメント

作業前に、関係する部分を読むこと。

- 仕様：`docs/プロンプト.md`
- シナリオ：`docs/大まかな流れ.md`、`docs/序章.md`、`docs/1章.md`

## 偽バグのルール（最重要）

- このゲームには意図的に仕込んだバグ（偽バグ）がある。偽バグは修正しない
- 意図的かどうか分からない挙動を見つけたら、直さずに質問する
- 偽バグの目印：一覧ファイルを正とし、コードにはID付きのコメントタグを付ける併用方式（方針のみ決定）
  - コードに偽バグのタグがある箇所は触らない
  - タグも一覧もない不審な挙動は、直さずに質問する
  - ID：名前式（例：`wall_clip`）
  - タグの書式：`# FAKE_BUG: wall_clip`
  - 一覧ファイルの形式：JSON
  - 一覧ファイルの置き場所：`data/fake_bugs.json`
  - JSONの項目：id、title、files、trigger、effect、requires、route、stage、hint、discovery、note（全件で全項目を書く。空は `[]` か `""`。変更の可能性あり）
  - 現在の一覧の中身は例。必要に応じて削除・変更する
  - 偽バグの発動は `BugRegistry.trigger("id")`（Autoload、`scripts/bug_registry.gd`）で記録する。一覧にないIDはエラーになる
  - 一覧とタグのずれの検査：`godot --headless --path . --script res://tools/check_fake_bugs.gd`（偽バグを追加・変更したら実行する）
  - 未決定：偽バグの発動状態をセーブに残すか（今はメモリ上のみ）、`requires` の意味（全部揃ったら発生か、どれかでよいか）

## 決定事項

- 戦闘形式：コマンド式（ターン制）
- 視点切替：別シーンへ切り替え（見下ろし用のシーンを別に作る）
- 基準解像度：320x180、整数倍拡大（ドット絵）。ストレッチモードは `canvas_items`（文字をくっきり表示するため）、起動はフルスクリーン

- バグ発見の判定：初めて「成功」したときに発見扱い（`discovery` が `normal` のバグのみ。`undetectable` は発見扱いにならない）。発見時に「バグを発見！」とテントウムシのドット絵の演出を出す
- バグ発見そのものはバフにしない。バフはストーリー由来にする方針で、詳細は骨格の実装後に決める（保留）
- エンカウント：敵の絵全体が画面に映った瞬間に暗転し、戦闘画面に切り替わる（ステージは一時停止して上に戦闘を重ねる）。コマンドは「たたかう・ぼうぎょ・にげる」の3つ（仮）
- ポーズ：Esc でメニュー（RESUME / BUG / EXIT）。EXIT でゲーム終了
- BUG（実績のようなバグ図鑑）：発見済みのバグはテントウムシ、未発見はシルエットで表示。マウスを合わせると、発見済みは短い名前（例：「壁抜け」）、未発見は「？？？」を表示。開いている間はマウスを有効化。Esc で PAUSE メニューに戻る
  - 載せるバグと表示名は `scripts/bug_book.gd` の `ENTRIES` に、実装したものから追加していく
  - 今後複数ページになる前提（1ページ8枠。2ページ以上になると「<」「>」が出る）
- 視点切替（別シーンへ切り替え、決定済みの方式）の最初の例：
  - 特定の壁（例：`triple_clip`）を右→左→右と3回連続でwall_clipすると、迷路シーン（別シーン）へ切り替わる
  - 迷路は1人称の3D（バックルームズ風）。薄暗い照明で、この場面だけモノクロ表示（`shaders/monochrome.gdshader`）。シーンは `scenes/maze_backrooms.tscn`
  - 迷路は普通に歩いて進める。ゴールへの正規の入口はなく、ゴール前の壁だけ薄く光っており、そこだけwall_clipできる（`maze_goal_clip`）
  - しゃがみはゴール前の区画でのみ可能（Ctrl / C）。しゃがむと視点が少し下がる
  - 操作：WASDで移動、マウスで視点、Shiftでダッシュ。ジャンプはなし
  - ゴールに着くと、通常ルートでは入手できないアイテム（仮：`castle_door_key`）を入手し、元のステージの元の場所へ戻る
  - 座標・誘導・アイテムの内容は仮
  - 既知の制約：迷路から戻る際は `change_scene_to_file` で元のステージを再読み込みするため、倒した敵などのステージ内の状態はリセットされる（状態管理は未解決事項のまま）
